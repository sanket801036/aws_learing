01

AWS Shared Responsibility Model

It defines the security and compliance responsibilities between AWS and the customer — in plain words, who makes sure the hardware and software are working properly and as per the rules.

  • Compliance = following the rules and laws made for data (GDPR, HIPAA, PCI-DSS).
  • Two sides only: AWS = security of the cloud. Customer = security in the cloud.

AWS Responsibility — security OF the cloud

ItemMeaningExample
Physical + facilityAWS keeps the building and facility safe.Guards and badge entry; you can never walk in.
Hardware & serversAWS buys, repairs and replaces the machines.A failed disk under your EC2 is replaced by AWS.
HypervisorSoftware AWS installs on the physical machine; runs many VMs on one server.Another customer's EC2 cannot read your instance.
Network (NI)Switches, routers, cables and the global backbone.Traffic between AZs runs on AWS's private fibre.

Customer Responsibility — security IN the cloud

ItemMeaningExample
DataThe data you store and process is yours to protect.You decide who can download a file from your S3 bucket.
IAM (the core)Permissions and access, so only authorized users get in.Intern gets read-only; MFA on root.

Remember: AWS protects the building, you protect your room.

Extra points from class

Host OS vs Guest OS — this is exactly why OS sits on both sides.

Managed byWhat it is
Host OSAWSThe OS on the physical machine, which runs the hypervisor.
Guest OSCustomerThe OS inside the VM you launch — your EC2's Linux or Windows.

Network config — stateful vs stateless firewall

Stateful — Security GroupStateless — NACL
Return trafficAutomatic — inbound allow kiya to reply apne aap jaata hai.Manual — inbound aur outbound dono rules likhne padte hain.
Works onInstance (ENI) levelSubnet level
RulesOnly allowAllow + deny
  • Inbound = request coming into your server. Outbound = traffic going out.

Encryption basics

  • Encryption = plain text → cipher text (unreadable). Decryption is the reverse.
  • Symmetric — one key for both encrypt and decrypt (fast; AES, used in S3/EBS).
  • Asymmetric — two keys: public encrypts, private decrypts (RSA; SSH key pair, TLS handshake).
  • At rest = stored data (S3, EBS) → encrypt with KMS. In transit = moving data → HTTPS / TLS.

AWS pricing

AWS charges on usage — how much you use, and for how long.

◀ INBOUND Data IN = free

Uploading into S3, EC2 or any AWS service costs nothing.

OUTBOUND ▶ Data OUT = paid

Data leaving AWS to the internet or another region is billed. First GB/month is usually free.

05

Root account

The first account created when you sign up. It has unrestricted access to everything.

PointMeaning
Unrestricted accessFull access to every service, IAM, billing and security settings.
Full permissionsCreate/delete IAM users, change billing, even close the account.
Security riskFull power = biggest target, so limit its use and enable MFA.
Primary useOnly setup and the few tasks IAM users cannot do.
Best practices: MFA on root → make an admin IAM user for daily work → never create root access keys → strong password → billing alerts on.
06

Support plans

Paid packages that give technical assistance, guidance and troubleshooting from AWS experts — architecture design, service issues, best practices.

Four plans: Basic → Developer → Business → Enterprise. Going up, the response time gets faster and the cost goes up.

Interview points

Hinglish me, jaise interview me bolna hai.

Shared Responsibility Model

"Who patches the OS?"

EC2 pe tum, RDS / Beanstalk / Lambda pe AWS. Ye sabse zyada poocha jaane wala trap hai.

Public S3 bucket se data leak — kiski galti?

Customer ki. Bucket policy hamesha tumhari. Real duniya me zyadatar cloud breach customer ki misconfiguration se hote hain, AWS ki galti se nahi.

OS aur Compliance dono ki list me kyun aate hain?

OS — host OS aur hypervisor AWS ka, EC2 ke andar wala guest OS tumhara. Compliance — AWS apne data center ka certification leta hai (ISO, SOC, PCI-DSS), us certified infra pe apni app ko rules ke hisaab se banana tumhara kaam. Isko bolte hain inherited controls.

SG vs NACL

Security Group stateful — reply apne aap allow. NACL stateless — dono taraf rule likhna padta hai. SG instance pe, NACL subnet pe. SG me sirf allow, NACL me deny bhi.

"AWS mera data encrypt kar deta hai?"

AWS tool deta hai (KMS, S3 encryption), par on karna aur keys manage karna customer ka kaam hai.

Yaad rakhne ka shortcut

"Ye cheez chhu sakte ho ya console me click karte ho?" Chhune wali (building, cable, server) = AWS. Click wali (SG, KMS, IAM) = customer. Aur keywords bolo — AWS = security of the cloud, customer = security in the cloud.

Pricing

Data IN free, data OUT paid

Sabse zyada poocha jaata hai. Internet se AWS me upload free, AWS se bahar nikaalna paid.

EC2 vs Lambda cost

EC2 chalu hai to paisa lagta rahega chahe traffic ho ya na ho; Lambda me sirf request chalne pe (per ms) charge. Kam ya uneven traffic = Lambda sasta.

EBS ka classic trap

EC2 stop karne se compute ka paisa band ho jata hai, par EBS volume ka storage charge chalta rehta hai. Unused volumes delete karo.

S3 aur Glacier

Sirf storage ka paisa nahi — PUT/GET requests aur transfer ka bhi lagta hai. Glacier storage me sasta, par retrieval ka alag charge.

Elastic IP — naya point

Feb 2024 se har public IPv4 pe $0.005/hour, chahe use ho ya na ho. Ye bolne se latest knowledge dikhti hai.

Cost vs availability trade-off

Same-AZ transfer free, cross-AZ aur cross-region paid. App aur DB ek AZ me rakho to bill kam — par HA ke liye multi-AZ chahiye. Ye trade-off wali baat interviewer sunna chahta hai.

"Cost kaise kam karein?"

Savings Plan / Reserved lo, batch kaam Spot pe chalao, S3 lifecycle se purana data Glacier me bhejo, Auto Scaling on rakho, unused EBS aur Elastic IP delete karo, aur Cost Explorer + Budgets se monitor karo.

Chhote points

DynamoDB ke 2 modes — On-Demand (uneven traffic) aur Provisioned (predictable me sasta). RDS me DB size tak backup free. Windows EC2 Linux se mehnga kyunki licence included. CloudFront bill kam karta hai — cache se origin hit kam aur uska outbound rate sasta.

Root Account

"Root se kaam kyun nahi karte?"

Ek galti ya password leak = poora account gaya. Root pe normal IAM policy laga bhi nahi sakte. Pehle din ka kaam: MFA on karo, admin IAM user banao, root lock karke rakho.

Root-only tasks

Account band karna, support plan badalna, account ka name/email/root password badalna, account ko AWS Organizations me move karna, aur galat S3 bucket policy theek karna.

Root ko rok kaun sakta hai?

IAM policy nahi — sirf AWS Organizations ka SCP (Service Control Policy). Aur root ki access key kabhi mat banao; ho to delete karo.
