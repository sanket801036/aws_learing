# THEORY

## 1. AWS Shared Responsibility Model

- It defines **security and compliance** responsibilities between **AWS** and the **customer**.
- Simple words: **kaun dekhega ki hardware aur software theek chal raha hai aur rules ke hisaab se hai** — AWS ya tum.
- **Compliance** = following the rules and laws made for data (GDPR, HIPAA, PCI-DSS).
- It has **two types**: AWS responsibility (security **of** the cloud) and Customer responsibility (security **in** the cloud).

### AWS Responsibility — Security **OF** the Cloud

| Item | Meaning | Practical example |
|---|---|---|
| **Physical + facility security** | AWS keeps the building and facility physically safe. | Guards and badge entry; you can never walk in. |
| **Hardware & servers** | AWS buys, repairs and replaces the machines. | A failed disk under your EC2 is replaced by AWS. |
| **Hypervisor** | Software AWS installs on the physical machine; it runs many VMs on one server. AWS secures it. | Another customer's EC2 cannot read your instance. |
| **Network infrastructure (NI)** | AWS protects switches, routers, cables and the global backbone. | Traffic between AZs runs on AWS's private fibre. |
| **Managed services** | AWS patches the software of its managed services. | AWS installs the MySQL patch on your RDS. |
| **Global infrastructure** | AWS builds and runs Regions, AZs and Edge Locations. | 3 AZs in Mumbai stay running for your app. |

### Customer Responsibility — Security **IN** the Cloud

| Item | Meaning | Practical example |
|---|---|---|
| **Data** | The data you **store and process** is yours to protect. | You decide who can download a file from your S3 bucket. |
| **IAM (the core)** | Manage permissions and access so that **only authorized users** get in — IAM users, groups, roles. | Give an intern read-only access; enable MFA on root. |
| **Application security** | You secure your code, software and OS patches. | Fix a SQL-injection bug; run OS updates on your EC2. |
| **Network configuration** | You set security groups, firewalls and VPC rules. | Open only port 443; keep the database subnet private. |
| **Encryption** | You encrypt data in transit and at rest, and manage keys. | Turn on S3 encryption with KMS; use HTTPS on the site. |
| **Compliance** | You make sure your AWS usage follows your industry's rules. | A hospital app must store patient data the HIPAA way. |

**Remember:** AWS protects the **building**, you protect your **room**.

### Extra points from class

**Host OS vs Guest OS** — *isi wajah se OS dono ki responsibility me aata hai*

| | Managed by | What it is |
|---|---|---|
| **Host OS** | **AWS** | The OS on the **physical machine**, which runs the hypervisor |
| **Guest OS** | **Customer** | The OS **inside the VM** you launch (your EC2's Linux/Windows) |

**Network config — Stateful vs Stateless firewall**

| | **Stateful** = Security Group | **Stateless** = NACL |
|---|---|---|
| Return traffic | Automatic — inbound allow kiya to reply apne aap jaata hai | Manual — inbound aur outbound dono rules likhne padte hain |
| Works on | Instance (ENI) level | Subnet level |
| Rules | Only **allow** rules | **Allow + deny** dono |

- **Inbound traffic** = request coming into your server. **Outbound traffic** = traffic going out (who will receive the request).

**Encryption basics**

- Encryption = **plain text → cipher text** (unreadable). Decryption = cipher text → plain text.
- **Symmetric** = ek hi key se encrypt aur decrypt (fast; AES — S3/EBS me use hota hai).
- **Asymmetric** = 2 keys — public se encrypt, private se decrypt (RSA — SSH key pair, TLS handshake).
- **Data at rest** = stored data (S3, EBS) → KMS se encrypt karo.
- **Data in transit** = travel karta hua data → HTTPS / TLS / SSL se protect karo.

## 2. Shared Responsibility by Service Model

The split changes with the service type. Moving **IaaS → PaaS → SaaS**, AWS takes more and you take less.

| Model | AWS example | AWS handles | You handle |
|---|---|---|---|
| **IaaS** | EC2 | Physical infra, hypervisor, network | OS, patching, application, data |
| **PaaS** | Elastic Beanstalk | Infra + OS + runtime, scaling | Application code, data |
| **SaaS** | Amazon QuickSight | Almost everything | Only your usage — data and user access |

**Rule:** more control = more responsibility.

|---|:---:|:---:|

| Data Encryption | | ✅ |

### Easy way to remember (4 – 3 – 2)

- **AWS = 4 physical things** → Physical, Network, Data Center, Hypervisor. *(the bottom layer, you can touch it)*
- **Customer = 3 config things** → Firewall/SG, Encryption, IAM. *(whatever you click in the console)*
- **Both = only 2** → **O**S and **C**ompliance. Yaad rakho: **"OC dono ka"**.

## 4. AWS Pricing Models

AWS charges on **usage** — how much you use, for how long.

| Factor | Service | Charged on |
|---|---|---|
| **Compute** | EC2 | Instance type, size, region, running hours |
| **Compute** | Lambda | Number of requests + duration (ms) + memory given |
| **Storage** | S3 | Data stored (GB), storage class (Standard/Glacier), requests (PUT/GET), transfer |
| **Storage** | EBS | Volume size, volume type (SSD/HDD), IOPS, snapshots |
| **Data transfer** | All services | Inbound **free**; outbound **paid** (first GB/month usually free); cross-region also paid |
| **Network** | VPC | Data transfer between VPCs/regions, VPN usage, PrivateLink |
| **Network** | CloudFront | Data transfer out, number of requests (HTTP/HTTPS), edge locations used |
| **Database** | RDS | Instance type, storage, backups, I/O, data transfer out of region |
| **Database** | DynamoDB | Read/Write capacity units, storage, backups and streams |
| **Database** | Aurora | Instance hours, storage, backup usage |
| **Extra** | ELB | Load balancer hours + data processed + requests handled |
| **Extra** | Elastic IP | Since **Feb 2024**, every public IPv4 costs **$0.005/hour** — attached ho ya idle |
| **Extra** | Licensing | Windows Server, Oracle DB ka licence cost alag se add hota hai |
| **Extra** | Region | Same service, different region = different price |

**Golden rule:** pay for **compute time + stored GB + data going out**.

### EC2 purchase options

| Option | When to use | Saving |
|---|---|---|
| **On-Demand** | Short / unpredictable work | 0% (costliest) |
| **Reserved / Savings Plan** | Steady 1–3 year workload | up to ~70% |
| **Spot** | Batch jobs that can be interrupted | up to ~90% |
| **Dedicated Host** | Licence or compliance needs own hardware | costliest |

### AWS pricing philosophy — 4 lines, ratt lo

1. **Pay as you go**
2. **Pay less when you reserve**
3. **Pay less by using more** (volume discount)
4. **Pay less as AWS grows** (AWS bada hota gaya, rates girte gaye)

## 5. AWS Root Account

The **first account created when you sign up** for AWS. It has **unrestricted access** to everything.

| Point | Meaning |
|---|---|
| **Unrestricted access** | Full access to every service, IAM, billing and security settings |
| **Full permissions** | Create/delete IAM users, change permissions, change billing, even close the account |
| **Security risk** | Full power = biggest target for hackers, so AWS says limit its use + enable MFA |
| **Primary use** | Only for setup and the few tasks that IAM users cannot do |

**Best practices:** enable **MFA** on root → make an admin IAM user for daily work → never create root access keys → strong password → turn on billing alerts.

## 6. AWS Support Plans

Support Plans = **paid packages** that give technical assistance, guidance and troubleshooting help from AWS experts (architecture design, service issues, best practices).

**4 types:** `Basic → Developer → Business → Enterprise`
Upar jaate jaate **response time fast** hota jaata hai aur **cost badhti** jaati hai.

# 🎯 Interview Points (Hinglish)

## Shared Responsibility Model

- **"Who patches the OS?"** → EC2: **you**. RDS / Beanstalk / Lambda: **AWS**. Ye sabse zyada poocha jaane wala trap hai.
- **Public S3 bucket se data leak — kiski galti?** → **Customer ki**. Bucket policy hamesha tumhari. Real duniya me zyadatar cloud breach customer ki misconfiguration se hote hain, AWS ki galti se nahi.
- **Security group 0.0.0.0/0 pe port 22 khula** → customer ki galti, AWS rokega nahi.
- **RDS managed hai fir bhi** — AWS engine patch karta hai, par **DB users, passwords aur encryption ka choice tumhara**.
- **OS dono ka kyun?** — AWS host OS + hypervisor patch karta hai; EC2 ke andar wala guest OS tum patch karte ho. RDS/Lambda me poora OS AWS ka.
- **Compliance dono ka kyun?** — AWS apne data center ka certification leta hai (ISO, SOC, PCI-DSS); us certified infra pe apni app ko rules ke hisaab se banana tumhara kaam. Isko bolte hain **inherited controls**.
- **Shortcut soch** — "ye cheez chhu sakte ho ya console me click karte ho?" Chhune wali (building, cable, server) = **AWS**. Click wali (SG, KMS, IAM) = **customer**.
- **Trap:** "AWS mera data encrypt kar deta hai?" → Bolo: AWS **tool deta hai** (KMS, S3 encryption), par **on karna aur keys manage karna customer ka kaam hai**.
- Sirf **2 rows dono ke** hain (OS + Compliance) — ye yaad rahega to aadhi table apne aap yaad rahegi.
- **SG vs NACL** (pakka poochha jaata hai) — Security Group **stateful** hai, reply apne aap allow ho jaata hai; NACL **stateless** hai, dono taraf rule likhna padta hai. SG instance pe lagta hai, NACL subnet pe. SG me sirf allow, NACL me deny bhi.
- **Host OS kiska, guest OS kiska?** — host OS aur hypervisor AWS ka, EC2 ke andar wala guest OS tumhara. Isi wajah se OS dono ki list me aata hai.
- Keywords bol ke dikhao: AWS = security **"of"** the cloud, customer = security **"in"** the cloud.

## Pricing

- **Data IN free, data OUT paid** — sabse zyada poocha jaata hai. Internet se AWS me upload free, AWS se bahar nikaalna paid.
- **EC2 vs Lambda** — EC2 chalu hai to paisa lagta rahega chahe traffic ho ya na ho; Lambda me sirf request chalne pe (per ms) charge. Kam ya uneven traffic = Lambda sasta.
- **EBS ka classic trap** — EC2 stop karne se compute ka paisa band, par **EBS volume ka storage charge chalta rehta hai**. Unused volumes delete karo.
- **S3 me sirf storage ka paisa nahi** — PUT/GET requests aur transfer ka bhi lagta hai. **Glacier storage me sasta, par retrieval ka alag charge**.
- **Elastic IP wala naya point** — Feb 2024 se har public IPv4 pe charge, chahe use ho ya na ho. Ye bolne se latest knowledge dikhti hai.
- **Same AZ transfer free, cross-AZ aur cross-region paid** — app aur DB ek AZ me rakho to bill kam, par HA ke liye multi-AZ chahiye. Ye **cost vs availability trade-off** poochha jaata hai.
- **CloudFront bill kam karta hai** — cache ki wajah se origin se baar-baar data nahi nikalta, aur uska outbound rate EC2 se sasta hai.
- **DynamoDB ke 2 modes** — On-Demand (per request, uneven traffic) aur Provisioned (RCU/WCU set karo, predictable traffic me sasta).
- **RDS backup** — DB ke size tak backup storage free, usse zyada pe charge.
- **Windows EC2, Linux se mehnga** kyunki licence cost included hai.
- **Region se rate badalta hai** — same instance Mumbai aur N. Virginia me alag price.
- **"Cost kaise kam karein?"** (follow-up pakka aata hai) → Savings Plan/Reserved lo, batch kaam Spot pe, S3 lifecycle se purana data Glacier me, Auto Scaling on, unused EBS aur Elastic IP delete, aur Cost Explorer + Budgets se monitor.

## Root Account

- **"Root se kaam kyun nahi karte?"** — ek galti ya password leak = poora account gaya. Root pe normal IAM policy laga bhi nahi sakte. Isliye pehle din ka kaam: MFA on karo, admin IAM user banao, root lock karke rakho.
- **Root-only tasks yaad rakho** — account band karna, support plan badalna, account ka name/email/root password badalna, account ko AWS Organizations me move karna, aur galat S3 bucket policy theek karna.
- **Root ki access key kabhi mat banao** — agar hai to delete karo. Ye best practice line seedhi bolne layak hai.
- **Root ko rok kaun sakta hai?** — IAM policy nahi, sirf **AWS Organizations ka SCP** (Service Control Policy).
